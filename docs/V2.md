# Cidade do Sabor V2 — entrega e revisão

> Documento histórico da V2. Os fluxos atuais de acesso, checkout e persistência estão descritos em [V3](V3.md).

A V2 evolui o frontend existente. Todas as páginas V1 e o visual aprovado foram mantidos, incluindo fotos horizontais 3:2 sem corte, hambúrgueres em PNG transparente, cabeçalho centralizado e carrossel inicial. O botão rápido do destaque inicial adiciona a receita padrão; os cards abrem a personalização.

## Regras centralizadas

Todos os preços são centavos inteiros: `2990` significa R$ 29,90. O preço unitário é a soma do preço base, dos adicionais e dos acréscimos dos grupos. No combo para duas pessoas, cada opção de hambúrguer, batata e bebida tem seu acréscimo multiplicado por dois; os adicionais avulsos são cobrados uma vez por unidade de combo. A interface explicita essa regra.

Retirar ingredientes não altera o preço. Adicionais indisponíveis são desabilitados. Bacon e carne extra não podem ser adicionados ao hambúrguer vegetariano, inclusive quando selecionado no combo. O combo vegetariano pode incluir acompanhamentos não vegetarianos quando escolhidos explicitamente.

Itens com mesmo produto, ingredientes retirados, adicionais, ponto da carne, observação e escolhas do combo são agrupados. A ordem dos adicionais não muda a identidade; espaços nas extremidades das observações são removidos. Configurações diferentes permanecem em linhas separadas. Limites: 99 unidades por configuração, 100 combinações e observações com até 300 caracteres.

O armazenamento mantém a chave legada `cidade-do-sabor:cart:v1` para migrar os carrinhos existentes, mas grava um envelope com `version: 2`. Dados recuperados são normalizados; IDs desconhecidos, preços adulterados, opções incompatíveis e quantidades inválidas não são confiados. Os preços são sempre recalculados a partir dos dados locais atuais. Eventos de armazenamento sincronizam as abas sem regravação em ciclo. Edições simultâneas em abas diferentes seguem a última gravação disponível; não há serviço de sincronização remota.

## Checkout e privacidade

Delivery exige CEP, rua, número (ou S/N), bairro, cidade e estado. Complemento e referência são opcionais. Retirada não exige endereço e não cobra frete simulado. Nome e telefone com DDD são obrigatórios em ambos.

O frete de delivery é R$ 6,00 **fictícios**, definido em `checkoutSettings.deliveryFeeCents`. Prazo e disponibilidade permanecem indisponíveis. Escolher PIX, crédito, débito ou dinheiro não cria uma transação. Não há campos de dados de cartão, senhas ou chave PIX.

Ao clicar em **Simular pedido**, os dados válidos aparecem apenas na tela de sucesso, em memória, com resumo da seleção. Não são gravados no localStorage, enviados pela rede nem usados para criar pedidos. Recarregar a página encerra essa tela. O carrinho é mantido para novos testes. Use dados fictícios, inclusive nas observações dos produtos, que fazem parte do carrinho local.

## Executar e verificar

Validação desta entrega: build de produção, lint e TypeScript aprovados; 49 testes passaram (7 de lógica e 42 fluxos em Chromium desktop/mobile). A personalização, o carrinho e o checkout também foram revisados visualmente, com conferência de layout nas larguras de 1440, 768 e 390 pixels.

```bash
npm ci
npm run dev
```

No Windows com restrição de scripts do PowerShell, use `npm.cmd` em lugar de `npm`.

```bash
npm run lint
npm run typecheck
npm run build
npm run test:e2e
```

`npm run test:logic` executa somente os testes de lógica. O runner completo executa lógica e fluxos em Chromium desktop e mobile. Faça o build antes dos testes e deixe a porta 3000 livre, ou use o servidor de produção do mesmo build. As instruções de instalação do Chromium estão no README.

## Limitações

O destaque inicial respeita a preferência de movimento reduzido do dispositivo. Quando ela está ativa, a interface oferece o botão **Ativar animação** para uma escolha explícita de animação completa apenas nesse destaque. Essa escolha permanece durante a sessão da aba e pode ser revertida por **Reduzir movimento**.

Não há backend, banco de dados, autenticação, pedidos reais, gateway de pagamento, consulta de frete, geolocalização, envio automático por WhatsApp ou integração obrigatória. Nada nesta versão confirma atendimento, entrega, retirada, disponibilidade de estoque ou preço de um estabelecimento real. Os testes de acessibilidade automáticos não substituem revisão manual com tecnologias assistivas.
